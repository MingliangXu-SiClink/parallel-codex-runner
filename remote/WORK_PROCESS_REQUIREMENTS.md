# 结构化工作过程需求文档

状态：用户已确认；首批已安装并发布，尚未满足全文的全部验收要求。日期：2026-09-10。

实际交付与未完成项见 [本轮验收记录](qa/2026-09-10-work-process.md)。以下仍保留完整目标，不把未覆盖项目改写为已完成。

## 1. 目标与范围

将当前偏日志卡片的工作过程，改为参考截图中的“可折叠标题 + 紧凑操作列表”：用户能直接看懂 Agent 读了什么、搜了什么、改了什么、运行到哪里；需要时再查看原始命令、输出和 Diff。

**改造顺序：pcrd 提供事实 → 共享协议传递事实 → macOS / Android 展示事实。不能只在客户端改图标、猜命令。**

| 本期包含 | 本期不包含 |
| --- | --- |
| 工具事件结构化、状态合并、过程列表、详情、缓存恢复、兼容与真实验收 | 重做侧栏、输入框、Agent 选择器或结果面板 |
| macOS 优先交付；Android 使用同一协议完成对应展示 | 改变发送、采用、续问、后台队列的业务规则 |
| 中英文系统文案、键盘与触摸操作、无障碍、性能回归 | 新增独立日志服务、数据库体系或额外翻译模型调用 |

改造前的问题：命令、文件操作主要被压成展示文本，客户端缺少可靠的操作身份和结构化目标。首批实现已增加 pcrd 规范化记录、共享生成类型和两端展示；历史工作过程补全、文件快照等尚不能据此视为完成。

## 2. 用户看到什么

一条操作采用固定结构：**类型图标 + 状态动词 + 操作对象 + 可选结果**。不显示重复的“命令”“活动”大标题，不为每条操作铺灰色卡片。

| 操作 | 进行中示例 | 完成后示例 |
| --- | --- | --- |
| 读取文件 | 正在读取 changes.txt | 已读取 changes.txt |
| 搜索文件 | 正在 current.tex 中搜索“equation” | 已在 current.tex 中搜索“equation” |
| 查看目录 | 正在查看 src | 已查看 src |
| 执行命令 | 正在运行 latexmk … | 已运行 latexmk … · 6 秒 |
| 文件改动 | 正在修改 current.tex | 已修改 current.tex · +37 -2 |
| 创建 / 删除 | 正在创建 comparison.tex | 已创建 comparison.tex |
| 多文件改动 | 正在修改 3 个文件 | 已修改 3 个文件 |
| 网页搜索 | 正在搜索“SwiftUI 布局” | 已搜索“SwiftUI 布局” |
| 无法识别的工具 | 正在执行 {工具名} | 已执行 {工具名} |

- 文件名是可点击对象；同名文件用必要的相对路径区分。长路径中间省略，长命令、查询最多两行，详情保留全文。
- 耗时、行数、匹配数只有可靠数据才显示。未知值不显示为 `0`；二进制改动不伪造行数；部分文件缺统计时不显示假总数。
- 操作失败在本行显示“读取失败 / 运行失败”等明确状态，展开查看原因；取消显示“已取消”，不用红色冒充失败。
- 普通回复和最终回答仍是正文；上游公开的思考摘要属于工作过程。不得把自然回复塞进工具列表，也不得复制一份最终回答。

## 3. 分组与交互

1. **时间顺序**：按操作开始的事件顺序排列，完成后原位更新，不移动到列表末尾。并行操作允许交错显示，不能串到其他 Agent。
2. **工作段**：连续的思考摘要与工具操作组成一个工作段；自然回复出现时结束该段。不能把前面的过程统一搬到最后一条回复之后。
3. **标题**：有明确上游阶段标识时可显示阶段标题；没有则显示“工作过程”，不通过关键词臆造任务阶段。
4. **展开规则**：首次打开时，正在执行的工作段展开，已结束段收起；已展示内容不会因完成、轮询或断线重连突然折叠。用户手动选择的展开状态优先，并按对话、回合、Agent、工作段保存。
5. **操作详情**：macOS 点击操作行原位展开完整命令、目标、退出码、错误、输出或改动列表；Android 使用原生底部详情面板，系统返回关闭详情而不离开对话。文件链接单独响应。长输出和 Diff 按需分页加载，不预加载全文。
6. **只读行为**：展开、复制、预览文件、查看 Diff 都不能触发重新执行、采用结果、停止 Agent 或发送消息。详情加载失败只影响本条详情。
7. **历史与切换**：历史回合只关联当时采用的 Agent；当前回合切换 Agent 只替换当前候选内容。先准备目标内容再替换，不能清空后加载。

历史工作过程默认收起；已有事件可恢复，已被清理的内容明确显示不可用，不从另一个 Agent 或当前工作区拼补。只统一现有设计文档中与本节冲突的工作过程规则，不借此修改导航布局。

## 4. 视觉与语言

- 与回答正文共用阅读列；图标固定宽度，文字首行基线一致，换行对齐文字起点。思考标题不能额外缩进一层，状态更新不能挤动相邻列。
- macOS 默认视觉行高约 24–28 pt，随字号和换行增长；使用系统字体与 SF Symbols。正文用常规字体，命令片段才用等宽字体。
- 已完成操作用可读的次级文字，正在执行的操作稍突出；只有失败需要错误色。不依赖颜色区分状态，不给每条历史操作保留旋转动画。
- 悬停只轻微强调可点击区域，不改变尺寸。深浅色、应用字号缩放、最小窗口宽度均不得遮挡、溢出或出现白底白字。
- macOS 支持 Tab 聚焦、Enter / Space 展开、VoiceOver 朗读类型与状态；Android 使用原生图标和触摸区域，不小于 48 dp，不机械复制桌面布局。
- 系统动词、状态、单位、错误说明随中英文设置变化；路径、命令、查询原文不翻译。
- 上游自由文本标题不假装已经翻译：无对应语言标题时，主标题使用本地化的“工作过程”，展开后保留原文；任意阶段标题的自动翻译不纳入本期。

## 5. pcrd 的职责

**集中完成识别、归并与事实保存，客户端不再各写一套命令解析。**

| 要求 | 规则 |
| --- | --- |
| 优先取结构化数据 | 优先使用上游工具类型、参数、目标文件、状态和改动事件；不能假定 CLI 已提供全部字段 |
| 保守识别命令 | 仅识别语义明确的常见读取、搜索、目录命令；使用参数解析，不靠一条宽泛正则。复杂脚本、管道、重定向或含副作用的组合保留为普通命令 |
| 不制造行为证据 | 不为识别目的执行命令；运行了 Python 脚本不等于“已读取文件”；搜索无匹配按工具语义处理，不直接当作失败 |
| 一次调用一条记录 | 开始、更新、完成合并到同一操作；分页、重放、断线补发不重复；相同命令再次调用或重试是新操作 |
| 可靠归属与顺序 | 身份包含 Run、Agent、尝试及操作标识；开始顺序固定，按事件序号应用更新。旧消息不能覆盖新状态或使终态退回运行中 |
| 时间与改动准确 | 优先使用上游耗时；有完整起止记录才计算并标明依据，不用客户端收到消息的时间算耗时。单次 Diff / 行数来自该次操作，不能拿整个 Run 的累计 Diff 冒充 |
| 恢复与异常 | 原始运行事件为事实来源，结构化缓存可重建；pcrd 重启后保留身份与顺序。失联不等于失败；恢复后既无法确认仍在执行、又无结束记录时显示状态待确认，不能长期假装运行中 |

复用既有事件存储与 `runs.agent` 分页链路；规范化处理不得阻塞 Agent 执行。不得每收到一条日志就扫描整个工作区、计算全仓库 Diff 或重读完整日志。

## 6. 共享数据契约

在现有 transcript Item 上增加可选的结构化操作数据，保留原有 `text`、`kind` 等兼容字段。下表是最小字段语义，具体字段名随协议评审确定。

| 数据 | 要求 |
| --- | --- |
| 上下文 | 复用既有 Machine / Workspace / Conversation / Turn / Run / Agent 关联，不重复塞进每行文本 |
| 操作身份 | 稳定 `operation_id`，关联执行尝试；缺上游 ID 时由 pcrd 根据可靠的调用关联生成并持久化。无法关联的旧事件保留原文，禁止按相同文本硬合并 |
| 顺序 | 首次事件序号、最新事件序号，用于固定位置、去重和拒绝过期更新 |
| 类型与状态 | 类型至少覆盖读取、搜索、目录、命令、文件改动、网页搜索、其他；状态统一为运行中、完成、失败、取消、未知 |
| 操作对象 | 文件 / 目录目标、搜索范围、查询、命令；保留结构，不让客户端从展示句子反推字段 |
| 时间 | 可空的开始、结束、耗时及其来源；未获得数据与实际为零必须可区分 |
| 文件变化 | 每个文件的路径、创建 / 修改 / 删除 / 重命名类型；可空的新增 / 删除行数及单次 Diff 引用 |
| 分组 | 可选的上游阶段标识、公开标题；没有时允许按连续工作段展示 |
| 详情 | 原始输出、错误、退出码、文件快照或 Diff 的受控引用；大内容按字节与条数限制分页 |
| 可用性 | 能区分未提供、加载中、已清理、失败，不能用空字符串掩盖原因 |

- 类型由单一协议定义生成 Python、Kotlin、Swift，并纳入现有生成检查；不再手写三套新增枚举。
- 旧客户端连接新 pcrd 继续使用原结构；新客户端连接旧 pcrd 回退为紧凑的普通命令 / 文本行。未知字段或类型不能导致整个对话打不开。
- 新能力通过兼容字段或能力协商提供，不能让仅有展示增强的升级迫使用户迁移运行状态。旧历史可按已有原始事件补全，缺失的数据保持未知。
- Relay 保持传输职责，不解析、翻译或重新归并工具事件。

## 7. 文件与详情正确性

- 文件预览必须定位到实际执行的机器、工作区、Agent 候选及相关版本。远端路径不能默认打开本机同名文件，临时候选路径不能伪装成原工作区文件。
- 有操作时的快照则显示对应版本；只有当前文件时必须明确标为“当前文件”，不能冒充操作当时内容。单次 Diff 不可用时，不自动替换成累计 Diff。
- 路径与详情请求沿用现有授权校验；不因新增链接扩大文件访问权限，不自动执行文件。命令参数中的凭据不得因摘要、复制或详情功能被新增暴露。

## 8. 流畅性与缓存

- 同一操作只更新同一行，不重建整个 transcript；展开前完成必要的高度计算，再提交布局，不能先画新文本、下一帧才撑高旧单元格。
- 展开 / 收起以点击行作为滚动锚点；不得出现文字叠在一起、闪白、跳到其他回复。不能用遮罩或延时隐藏代替修复布局。
- 用户向上阅读时新事件不强制拉到底部；只有原本处于跟随底部状态才继续跟随。状态文字变化不能改变 Agent 选择条或输入框位置。
- 缓存按机器、对话、回合、Agent 隔离；恢复先显示可用缓存，再增量校正。保留展开状态和阅读位置，过期异步响应不得写入另一对话。
- 解析、磁盘读取、输出分页和 Diff 计算不能放在 UI 主线程；尊重系统减少动态效果设置。

## 9. 验收标准

以下是完整验收要求。首批实现仅有部分通过，逐项证据和缺口见本轮验收记录。

| 场景 | 通过标准 |
| --- | --- |
| 真实操作 | 实际运行文件读取、搜索含零匹配、目录查看、成功 / 失败命令、取消、重试、多文件与二进制改动；类型、对象、状态与实际一致 |
| 去重与顺序 | 开始 / 更新 / 完成分布在不同页面；重复补发、旧事件晚到、相同命令连续执行后，仍一调用一行、位置不乱、终态不回退 |
| 详情 | 长命令、中文与空格路径、同名文件、长输出、单次 Diff、已清理文件均能正确查看或明确说明不可用 |
| 会话隔离 | 运行中切换 Agent、切换对话、续问、退出恢复、跨端查看后，无串内容、历史跳变、隐式采用或重复发送 |
| 展开流畅性 | 真实客户端连续展开 / 收起至少 30 次并录屏逐帧检查；无重叠、闪白、先清空。除滚动范围被夹紧外，点击行锚点位移不超过 1 pt / dp |
| 视觉 | 深浅色、默认与放大字号、窄 / 宽窗口、Android 不同尺寸；与参考截图对照密度、对齐和层级，不要求两端像素级复制 |
| 性能 | 以 1,000 条操作、3 个 Agent、至少 10 MB 延迟加载输出验收；已缓存内容展开至首次稳定布局 P95 ≤ 100 ms，数据到达后的可见状态更新 P95 ≤ 200 ms，网络等待单独记录 |
| 资源 | 同机同数据记录修改前后的 CPU、内存、主线程长任务与请求量；稳定空闲时无新增持续工作，无每次更新随全量历史增长的扫描 |
| 兼容 | 旧客户端 / 新 pcrd、新客户端 / 旧 pcrd、旧历史、旧缓存、未知事件类型全部可读，不影响发送与续问 |

性能数据需注明设备型号、系统、构建类型与样本次数，修改前后使用相同条件。交付必须包含：相关自动化回归、真实构建、签名安装或发布、已安装客户端操作记录、截图 / 录屏、实际版本和未通过项。Android 在已获准的模拟器上验收，不操作实体手机；未做真实验收的项目不得记为完成。

## 10. 实施与评审

1. **协议与 pcrd**：确认实际 CLI 事件字段，落实规范化、稳定身份、详情引用和兼容；用保存事件及真实任务核对事实。
2. **macOS**：接入紧凑列表、独立详情、原位更新和滚动保持；构建、签名、安装后完成视觉及操作验收。
3. **Android**：复用协议和状态语义，适配触摸、系统返回与生命周期，完成跨端验收并发布可更新的签名版本。
4. **发布检查**：旧协议验证通过再升级 pcrd；有活跃任务时不强行重启。核验实际运行版本，不以安装包生成代替交付。

用户已确认并开始实施：**采用无卡片的紧凑操作行；先改 pcrd 和共享协议再改展示；缺失事实明确缺失，不通过猜测补齐。** 尚未通过的验收项继续保留，不因首批版本发布而关闭。
