## Additional Confirmed Production Root

The initial management activation was blocked before mutation by two user-confirmed Agent answers that existed durably on the Mac but still had `state=open`, `delivery=none`, no answer ID and no answer values at the server. They were neither native queued answers nor delivered responses.

`ClientWindowContent` started `AgentAnswerOutbox` for additional windows only. The primary scene instead hosts `ContentView` directly. Consequently an ordinary main-window-only session never started the background sender even after a user committed an answer. Previous answer tests explicitly started that sender and therefore missed the production registration path.

459 moves this idempotent startup into the shared `ClientWindowRegistrationView.viewDidMoveToWindow` hook used by both primary and additional windows. The original confirmed answer IDs, bodies and values remain immutable; the normal sender reads the original question receipt before delivering and reconciles an already-received answer without another submission. No maintenance script selects an answer or creates a new answer identity.
