# 工作过程对齐与对话工具验收

本轮接续 `2026-09-10-work-process.md`，修复截图中的对齐问题，并交付已经确认的文件预览、差异审阅、选段引用、Agent 比较、正文搜索和独立窗口。没有重做侧栏，也没有改动用户已有的仓库迁移或替用户提交 Git。

## 实际问题与修复

- 思考摘要和操作行使用不同的左侧留白。现在共用图标列和正文起点，思考摘要增加图标；命令、搜索、文件操作、展开详情也使用同一文字起点。
- 展开详情时集合的数据数量先于 AppKit 批量更新改变，可能出现行数不一致。现在在批量更新事务内切换数据，并在最终测量后恢复原点击位置。
- 真实点击操作行发现崩溃：`hitTest` 内调用 `NSTextView.characterIndexForInsertion`，再次进入窗口命中测试造成无限递归。改为通过 TextKit 布局管理器直接查询字形及字符位置，并检查实际字形范围，不再递归命中测试。
- 流式快照缺少稳定消息身份，部分回答会重复累积。pcrd 为快照附带执行尝试与上游消息的稳定 ID；客户端完整刷新先分页加载，再一次替换，失败时保留已显示内容。
- 原执行通道不能可靠保留单次修改的 Diff。新增共享 Codex app-server 执行适配，保存实际命令输出、文件变更和单次 Diff；只在尚未发送执行请求时允许回退，避免重复执行。继续使用既有 Run、取消和 finalize 流程。
- PNG、部分图片和 Office 文件的相对路径被误判为网站。两端共同修复文件分类；`preview.png` 现在作为工作区文件读取，显式 HTTPS 和真实域名仍按网站处理。
- Agent 比较请求传入 `event_limit=0`，即使不读取事件也被服务端参数校验拒绝。修正为合法分页参数，真实回答比较现已可用。
- 文件预览原先过度挤压正文。macOS 14 及以上改用原生 inspector，默认宽度 440 pt，可在 280–640 pt 调整；macOS 13 保留 sheet 回退。长代码可以水平滚动；文件下载提示改为紧凑面板，不再横跨整个窗口。

## 测试与性能

- Python 全量：614 项通过，410.181 秒；后续稳定消息 ID 修改的相关 129 项回归通过。两次不累加成一个测试总数。
- macOS 客户端契约检查通过；最终原生测试 48 项、10 个测试组全部通过，28.611 秒。
- 原生回归包括实际附着窗口的命中测试、详情加载前后布局、展开锚点、长文本与水平滚动、文件链接分类、独立窗口状态和稳定消息去重。
- Android 单测、`lintDebug`、生产构建通过；最后文件链接回归与构建耗时 48 秒，随后通过仓库脚本完成签名 lineage 处理。
- 1,000 条合成操作、30 次热展开布局基准 P95 为 81.772 ms。这是批量布局成本，不能当作 60 fps、无掉帧或比 ChatGPT 更快的证明。
- 诊断期间的事件队列注入测试曾导致测试进程提前退出，即使退出码为 0 也不算全套通过；已移除此注入，以上 48 项来自完整结束的最终测试日志。

设计参考采用用户提供的真实客户端截图、安装版 Codex 的 app-server 类型定义以及 Apple 原生 inspector API。没有声称获得 ChatGPT 客户端源码，也没有完成与 ChatGPT 同机同负载的性能对照。
