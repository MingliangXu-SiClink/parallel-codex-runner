# macOS app icon acceptance - 2026-09-26

## Scope and diagnosis

- Preserve the approved stacked-card artwork. Change macOS packaging only.
- The shared PNG has a nearly opaque face and faint transparency outside it.
  On macOS 26.6.2 this was interpreted as a floating icon and wrapped in a white
  backing tile. Padding alone did not fix it.
- After opacity normalization, the 16/32 px 1x representations still reproduced
  the problem: `iconutil` stored them in legacy ARGB form. Using their PNG-backed
  Retina representations also fixed native 1x rendering.
- An in-place update initially left the old appearance in the native About
  panel even though `NSWorkspace` rendered the new file correctly. The final
  bundle uses `ParallelCodex.icns`, replacing the old resource identifier, and
  was installed as a complete bundle. The About panel then showed the original
  dark artwork without the white frame. No global icon cache or Dock reset.

## Implementation

- Added `build-app-icon.swift` to normalize alpha, preserve color, add the macOS
  canvas gutter, and generate eight PNG-backed iconset slots.
- Kept Apple's `iconutil` and the existing local signing pipeline.
- Added icon regression checks to `test-client.sh`: declared sizes, transparent
  perimeter, opaque face, ICNS decoding, and real Icon Services rendering at
  16, 32, 64, 128, 256, 512, and 1024 pixels.
- The shared master remained byte-identical (SHA-256
  `04bf291769e0ab044491ec90a4754f36dec9b9b7d45daf2b4202726d0cc71846`).
  No Android, pcrd, Relay, or app interaction code changed.
