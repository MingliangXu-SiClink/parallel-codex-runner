# macOS 连续布局与流式阅读验收

日期：2026-09-26。版本：0.1.385（385）。仅修改和更新 macOS 客户端。

## 根因与修改

1. 左侧栏原先通过条件分支移除整个视图，右侧栏通过增删 split item 切换。现在两侧均保留原生分栏及承载视图，使用 220 ms 的原生折叠动画；不在开关时重新设置用户拖动后的宽度。
2. 流式回复原先重新加载 collection item。现在同一消息更新原有 NSTextView；属性未变化的前缀保留，仅追加新增内容，Markdown 样式变化时仍应用正确样式。删除了助手回复不需要的整段自然宽度测量。
3. 自动跟随原先直接修改滚动位置。现在使用可打断、可重新定向的 160 ms 跟随；手动滚动、拖动滚动条、查找和切换上下文会取消旧的跟随请求。
4. 长文本原先等窗口拖动结束才重新排版。现在拖动期间以最多 30 Hz 合并可见内容排版，结束时做精确布局，并在同一帧恢复阅读锚点。
5. 窄窗口打开文件时的横向定位改为连续移动。侧栏开关保留单一固定入口，避免展开/收起过程中两个按钮交换位置；正常窗口和全屏分别遵守原生标题栏布局。

动画在系统“减少动态效果”开启时关闭。首次恢复对话、历史定位仍采用确定的直接恢复，不人为添加逐字打字延迟，也没有改变服务器流式轮询频率。

## 实际客户端走查

使用独立 HOME 和本机 IPC 验收服务驱动真实客户端，没有启动真实计费 Agent。初版走查覆盖浅色界面，最终签名构建的独立副本覆盖深色界面、普通窗口及系统全屏。

- 54 段长回答加 150 次连续消息快照，内容原位更新，无重复堆叠。
- 从底部回看旧段落后，后续快照继续到达但不夺回阅读位置；“跳到最新内容”可恢复跟随。
- 输入未发送草稿后反复开关侧栏，输入焦点和草稿保持；连续切换后侧栏宽度仍为原来的 286 pt。
- 运行中打开结果详情、Python 全文差异；结果详情保留，窄窗口可横向查看文件；退出全屏后仍可打开和关闭文件。
- 全屏进入和退出后内容持续可见，最终稳定画面没有遗留白色覆盖条。
- 最终规范数据走查未出现 Auto Layout 冲突或 AttributeGraph 循环；日志仅有系统输入法 IMK 提示。

测试数据曾错误地把每个完整回复快照当作独立消息，造成重复累积和高 CPU。已修正为实际协议的全局消息 ID，清除的仅是独立验收 HOME 中这次错误数据的缓存，随后重新完成流式验收；这段失败不计入通过结果。

正式客户端安装后，恢复已有 34 次提问的对话和 3,661 项文件修改列表。左右栏往返后，左栏 274 pt、结果栏 300 pt 均恢复；正文滚动位置回到相同值 `0.9588568612958857`。没有发送消息或改变 Agent 选择。稳定时单次进程采样约 2.1% CPU、315 MiB RSS；这是观察值，不是完整性能基准。
